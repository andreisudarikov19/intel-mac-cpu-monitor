# v1.2.3 — Sleep/wake SMC reset

After the Mac woke from sleep, CPU package, ambient air, and RAM keys would show "No data" persistently until Stream Deck restarted. The AppleSMC connection went stale for package-level keys, but the helper kept polling and the supervisor's stale-watch didn't fire.

- **Stale AppleSMC after sleep/wake**: the helper now detects long pauses between timer ticks (> 10 s gap = process was paused) and recycles its IOKit connection via a new `SMC.reset()` method. First post-wake tick shows live data again.
- **Affected sensors**: package-level keys (`TCAD`, `TC0F`, `TA0P`, `Ts0S`, and friends). Per-core CPU, GPU, fans, and SSD were unaffected because their reads go through different internal routing.
- **Detection is heuristic, not event-driven**: the timer is supposed to fire every 1 s; > 10 s gap triggers reset. Catches sleep/wake, SIGSTOP, debugger attach, anything that pauses the process. False positives are harmless (a redundant `IOServiceClose` + `IOServiceOpen` costs ~µs).
- **Fallback**: if `SMC.reset()` itself fails (rare — would require AppleSMC kext to have unloaded), the helper exits and the plugin supervisor respawns it.

No new SMC keys, no new actions, no UI changes. Tests unchanged.
