# v1.3.3 — PI poll fix, revert verification

Two issues reported against v1.3.2.

- **PI slider didn't hide** when switching back to "Plugin default" after having been set to "This key only". sdpi-components' value-change DOM events fire inconsistently when the dropdown returns to its initial option. Replaced the event-listener approach with a 5 Hz `setInterval` poll on the dropdown's `value` property — bulletproof against whatever events sdpi-components decides to emit.
- **Visible sample count and buffer capacity revert correctly** to the plugin default (30 / 45) when a per-tile override is cleared. Verified with 5 direct tests against the Hub covering default-when-no-override, override-applied, override-cleared-reverts, plugin-default-change-propagates, and out-of-range-override-clamps. No code change — confirmed an existing code path works as intended.
- **Added**: `Hub.getVisibleSampleCount(contextId)` and `Hub.getBufferCapacity(contextId)` — public accessors for tests; return `undefined` when the context isn't subscribed.

188 tests green (86 Swift + 102 TS).
