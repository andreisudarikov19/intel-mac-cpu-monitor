# v1.5.1 — Sleep/wake re-probe

The sleep/wake "No data" bug from v1.2.3 was not fully fixed — RAM temp, GPU temp, and ambient air temp still went persistently stale after waking.

- **Root cause**: v1.2.3 reset the SMC connection after wake but kept the same catalog, so the helper stayed bound to the exact sensor keys that had gone stale. A fresh process recovers because it re-runs the catalog probe and binds onto whichever candidate key works — that re-probe, not the connection reset, is the real fix. The `failureCounter` only respawns on *total* read failure, so partial staleness (3 sensors nil, the rest fine) was invisible and persisted.
- **Fix**: on wake (>10 s tick gap), keep emitting whatever still reads so the supervisor's stale-watch stays satisfied; after a 5 s settle, reset the connection *and* re-run the full catalog probe, then emit a fresh `ready` event. Bounded retry (up to 4 more attempts, 5 s apart) if a startup sensor is still missing — self-healing regardless of how long a Mac's SMC takes to recover.
- **Testing caveat**: the recovery mechanism is verified via a SIGSTOP/SIGCONT pause (same >10 s tick gap as sleep), but SIGSTOP doesn't make the SMC sensors actually go stale — only a real sleep/wake cycle does. Final confirmation requires hardware testing across a real sleep.
