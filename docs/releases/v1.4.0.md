# v1.4.0 — RAM Usage, Disk I/O, Uptime

Three new non-SMC metrics, plus a multi-line slide capability for future text-rich actions.

- **RAM Usage**: `host_statistics64` matches Activity Monitor's "Memory Used" = `(active + wired + compressed) × pageSize / totalPhysical`. Profile range 0–100 %, bands 50/75/90.
- **Disk I/O** (combined throughput): IOKit `IOBlockStorageDriver` cumulative counters, per-tick delta sampling. First tick reports 0 (no baseline); sleep/wake recovery resets the baseline too. Profile range 0–3 GB/s, bands 10 MB/s / 100 MB/s / 1 GB/s. Adaptive units in display text (KB/s / MB/s / GB/s).
- **Uptime**: Node `os.uptime()`. Slide-only — no graph or meter, tap and long-press are no-ops. Custom 3-line layout (`{W} weeks` / `{D} days` / `{H} hours`), largest unit on top, always three lines (zeros included), grey `#8E8E93` frame so the eye reads it as informational rather than state-driven.
- **Multi-line slide capability** (renderer): `RenderInput` gains `slideLines: string[]` and `slideAccent: string`. When `slideLines` is set + viewMode === "value", the slide stacks lines vertically with the header pushed up and smaller. Single-line slide behaviour unchanged.
- **Helper additions**: new file `Sources/smcreader/SystemStats.swift` for non-SMC metrics. New optional fields on `ReadingEvent`: `ramUsagePercent`, `diskReadBytesPerSec`, `diskWriteBytesPerSec`. `SMC.reset()` path now also resets the disk-I/O baseline.
